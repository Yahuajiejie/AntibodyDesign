# FLAb 抗体数据库中文解读

## 1. 数据库定位

FLAb 的全名是 Fitness Landscapes for Antibodies，可以理解为“抗体适应度景观数据库”。它不是一个专门用于从头生成抗体的模型库，而是一个用于训练、评估和比较蛋白质 AI 模型的抗体性质 benchmark。

这个数据库收集了大量公开研究中的抗体实验数据，覆盖治疗性抗体研发中常见的关键性质，包括结合能力、表达水平、热稳定性、免疫原性、聚集倾向、多反应性和药代动力学等。官方 README 中说明，FLAb 汇总了 241 个数据集和超过 300 万条抗体 assay 数据点。

对 Bio-OS 抗体设计赛题来说，FLAb 的主要价值不是直接给出 Nipah G 蛋白抗体，而是可以作为以下用途：

- 训练或微调抗体性质预测模型；
- 建立候选抗体的可开发性筛选规则；
- 比较不同蛋白语言模型、结构模型或简单理化指标对抗体性质的预测能力；
- 为最终 6 条候选抗体的表达、聚集、稳定性和结合潜力提供计算过滤依据。

## 2. 顶层目录结构

当前目录结构如下：

```text
FLAb/
├── data/                         # 原始抗体实验数据
├── models/                       # 各种模型和指标的打分脚本
├── score/                        # 零样本模型打分结果
├── examples/                     # 示例 notebook
├── Fig_biophysical_properties.png
├── README.md
└── LICENSE
```

官方 README 中还提到 `score_ft/`、`score_ablation/` 和 `envs/`，但当前本地目录里主要能看到 `data/`、`models/`、`score/` 和 `examples/`。这说明你本地拿到的版本可能不是完整仓库全部产物，或者部分目录尚未下载。

## 3. data 目录：核心原始数据

`data/` 是整个数据库最重要的部分。它按照治疗抗体性质分成 7 类：

```text
data/
├── aggregation/         # 聚集倾向相关数据
├── binding/             # 抗体-抗原结合能力相关数据
├── expression/          # 表达水平相关数据
├── immunogenicity/      # 免疫原性相关数据
├── pharmacokinetics/    # 药代动力学相关数据
├── polyreactivity/      # 多反应性/非特异性结合相关数据
└── thermostability/     # 热稳定性相关数据
```

此外，`data/` 下还有两个总索引文件：

```text
data/flab_metadata.csv
data/flab_metadata.json
```

其中 `flab_metadata.csv` 记录了每个数据集所属类别、大小、实验单位、关键词、论文来源、DOI、年份、许可证和序列相似性等信息。它适合用来做数据集筛选和统计。

## 4. CSV 数据格式

FLAb 中每个实验数据集通常是一个 CSV 文件。大多数 CSV 至少包含以下字段：

```text
heavy
fitness
```

如果是双链抗体，还会包含：

```text
light
```

因此常见格式是：

```text
heavy,light,实验测量值,fitness
```

或者对于纳米抗体/VHH：

```text
heavy,实验测量值,fitness
```

字段含义如下：

| 字段 | 含义 |
| --- | --- |
| `heavy` | 抗体重链可变区序列，VHH 数据中也通常放在这个字段 |
| `light` | 抗体轻链可变区序列，双链 Fv/scFv/Fab/IgG 数据常见 |
| `fitness` | 统一用于建模的实验目标值 |
| 其他字段 | 原始实验指标、抗原名称、设计轮次、突变信息、实验单位等 |

需要注意：`fitness` 并不总是“越大越好”。每个子目录的 README 里都有 `Direction of favorable values`，用箭头标记有利方向：

- `↑`：数值越大越好，例如表达量、Tm、部分 -log(Kd)；
- `↓`：数值越小越好，例如聚集倾向、多反应性、部分 retention time；
- 空白：方向不明确或不适合作为简单优劣目标。

建模时不能盲目把所有 `fitness` 都当成越大越好，否则会把聚集、多反应性等风险指标学反。

## 5. 七类数据的含义

### 5.1 binding：结合能力

`data/binding/` 是最大的一类，包含 132 个数据集。它记录抗体与不同抗原之间的结合能力，常见实验或指标包括：

- Kd；
- IC50；
- EC50；
- bind/no bind 二分类；
- SPR kinetics；
- AlphaSeq 预测亲和力；
- MAGMA-Seq；
- 流式或展示系统读数。

有些数据集使用 `-log(Kd)` 或 `-log(Kd [nM])`，这种情况下通常数值越大代表亲和力越强。也有些数据直接记录 Kd 或 EC50，此时理论上数值越小越好，但 FLAb 的 README 会标注处理后的有利方向。

对本次抗体设计赛题，binding 数据可以用于：

- 训练抗体亲和力预测模型；
- 评估候选抗体是否具有合理结合序列特征；
- 比较候选抗体与历史抗体优化数据的相似性；
- 作为 SPR 亲和力评分的计算代理指标。

不过要注意，FLAb 中 binding 数据的抗原非常分散，不一定包含 Nipah G protein。因此它更适合作为通用抗体结合能力建模数据，而不是目标抗原专属训练集。

### 5.2 expression：表达水平

`data/expression/` 记录抗体在不同表达体系中的表达量，例如 HEK titer、ER expression、µg/mL 等。

对比赛很重要，因为湿实验评分中表达水平占 20%。该目录可用于训练一个表达风险预测器，帮助过滤难表达候选。

推荐关注：

- `jain2017biophysical_HEK.csv`：临床阶段治疗性抗体，HEK 表达量；
- `garbinski2023_exp.csv`：表达量数据；
- `adams2017measuring_4420-fluorescein_exp_er.csv`：高通量表达相关数据。

### 5.3 aggregation：聚集倾向

`data/aggregation/` 记录抗体自相互作用、疏水性相关保留时间、SEC 单体比例、AC-SINS、HIC、CIC 等数据。

比赛湿实验中聚集倾向占 10%，所以这一类数据非常有用。它可以帮助建立聚集风险过滤器。

常见指标包括：

- AC-SINS；
- HIC retention time；
- SEC % monomer；
- CSI-BLI；
- SAS；
- CGE purity。

大多数聚集和自相互作用指标是风险指标，通常越低越好。但也有例外，例如 SEC 单体比例通常越高越好。因此必须逐个数据集参考 README 中的方向标记。

### 5.4 thermostability：热稳定性

`data/thermostability/` 记录 Tm、Tm1、DSF、nanoDSF 等指标。Tm 通常越高代表热稳定性越好。

虽然比赛评分没有直接写热稳定性，但稳定性差的抗体更容易表达失败、纯化失败或聚集，因此它适合作为候选筛选的辅助指标。

其中 `tresanco2023nbthermo_tm.csv` 是纳米抗体热稳定性数据，对于 VHH 路线尤其有参考价值。

### 5.5 polyreactivity：多反应性

`data/polyreactivity/` 记录抗体与非目标物质发生非特异性结合的风险，例如 PSR、BVP ELISA、CIC、SMAC、Heme、DNP 等。

多反应性高的抗体可能具有较差的可开发性，也可能引起非特异性背景信号。对于比赛中的 ELISA 和 SPR 验证，多反应性风险过高可能导致假阳性或不稳定表现。

一般来说，多反应性指标多数是越低越好。

### 5.6 immunogenicity：免疫原性

`data/immunogenicity/` 当前主要包含一个临床阶段治疗抗体的免疫原性数据集，指标是 `%ADA response`。ADA 是 anti-drug antibody，即抗药抗体反应。

这个类别对比赛短期湿实验不是最直接，但对治疗性抗体成药性非常重要。若做完整项目，可以把它作为人源化和长期开发风险指标。

### 5.7 pharmacokinetics：药代动力学

`data/pharmacokinetics/` 记录 FcRn、半衰期、清除率、heparin retention time 等指标。

比赛提交的是可变区，并统一加 Fc 标签表达，因此药代数据不是第一优先级。但可变区的电荷、疏水性和多反应性仍可能影响药代行为，因此这类数据可以作为高级可开发性评估的补充。

## 6. models 目录：模型打分脚本

`models/` 中包含大量 `scoring_*.py` 和 `ft_scoring_*.py` 脚本。它们用于用不同模型或指标对 FLAb 数据集进行评分。

脚本大致分为几类：

### 6.1 蛋白语言模型

包括：

```text
scoring_esm2_*.py
scoring_progen2_*.py
scoring_iglm.py
scoring_antiberty.py
scoring_ism_*.py
```

这些模型通常根据序列给出 likelihood、pseudo-perplexity 或 embedding-based score，用于判断某条抗体序列是否符合模型学到的自然/功能蛋白分布。

### 6.2 结构或逆折叠模型

包括：

```text
scoring_esmif.py
scoring_proteinmpnn.py
scoring_abmpnn.py
scoring_igfold.py
scoring_chai1.py
scoring_pyrosetta.py
```

这些脚本更接近结构建模或结构条件打分，可用于评估候选序列与结构的匹配程度、抗体结构合理性或复合物特征。

### 6.3 简单理化性质

包括：

```text
scoring_bp_aromaticity.py
scoring_bp_average_flexibility.py
scoring_bp_charge_at_7_4.py
scoring_bp_gravy.py
scoring_bp_instability_index.py
scoring_bp_isoelectric_point.py
scoring_bp_molecular_weight.py
```

这些基于 BioPython 或类似方法计算序列理化指标。虽然简单，但在表达、聚集、多反应性预测中常常很有解释性。

### 6.4 few-shot 微调脚本

以 `ft_scoring_*.py` 开头的脚本用于少样本监督训练，通常采用 train/val/test 切分。适合在某个 FLAb 子数据集上训练一个专门预测器。

对一个月项目来说，建议优先使用简单、稳定、可解释的 few-shot 模型，而不是一开始就训练复杂大模型。

## 7. score 目录：模型打分结果

`score/` 里保存了部分模型的零样本打分结果。当前本地可以看到的模型包括：

```text
score/antiberty/
score/esmif/
score/iglm/
score/mpnn/
score/progen/
score/pyrosetta/
```

每个模型目录下按性质类别继续分子目录，例如：

```text
score/esmif/binding/
score/esmif/aggregation/
score/esmif/expression/
score/esmif/tm/
```

这些结果一般包含：

- 每条序列的模型分数；
- 模型分数与实验 fitness 的相关性；
- 相关性统计检验；
- 可视化图。

因此，`score/` 可以用来回答一个问题：某个模型对某类抗体性质是否有预测能力。比如，如果某个模型在 aggregation 数据上相关性较好，就可以考虑把它加入候选抗体聚集风险筛选。

## 8. examples 目录

`examples/` 当前包含 notebook 示例，例如：

```text
FLAb_ZeroShotExample_IgLM_Expression.ipynb
Rosetta_TechTeaTime_23_03_2026.ipynb
```

这些 notebook 可用于学习如何调用模型脚本、读取数据集和做零样本打分。它们更像教程，不是数据库主体。

## 9. 与 Bio-OS 抗体设计赛题的关系

比赛复赛湿实验评分包括：

- SPR 亲和力：70%；
- 表达水平：20%；
- 聚集倾向：10%。

FLAb 正好覆盖这些维度：

| 比赛指标 | FLAb 对应数据 |
| --- | --- |
| 亲和力 / 结合能力 | `data/binding/` |
| 表达水平 | `data/expression/` |
| 聚集倾向 | `data/aggregation/` |
| 稳定性辅助 | `data/thermostability/` |
| 非特异性风险 | `data/polyreactivity/` |

因此，一个合理的使用方式是：

```text
生成候选抗体序列
  -> 抗体编号与合法性检查
  -> 与已知抗体相似性过滤
  -> 复合物结构预测与结合界面评分
  -> FLAb 训练/校准的表达预测器
  -> FLAb 训练/校准的聚集风险预测器
  -> 热稳定性和多反应性辅助过滤
  -> 最终选择 6 条候选
```

## 10. 建议的实际用法

如果只做一个月内可展示项目，建议不要试图把 FLAb 全部吃进去训练一个大模型，而是采用分层策略：

### 第一层：规则过滤

直接计算候选抗体的基本理化性质：

- 序列长度；
- CDR3 长度；
- 净电荷；
- pI；
- GRAVY；
- 芳香族比例；
- 半胱氨酸数量；
- N-糖基化位点；
- 疏水残基富集。

这些指标可以用 `models/scoring_bp_*.py` 类脚本或自己实现。

### 第二层：FLAb 监督预测器

从以下数据集中挑选代表性任务训练轻量模型：

- binding：选择 Kd、SPR 或 bind/no bind 数据；
- expression：选择 HEK titer 或 expression 数据；
- aggregation：选择 AC-SINS、HIC、SEC 数据；
- thermostability：选择 Tm 数据。

模型可以从简单方法开始：

- one-hot + ridge regression；
- ESM2 embedding + random forest；
- ESM2 embedding + XGBoost；
- Antiberty/IgLM embedding + MLP。

### 第三层：候选排序

将结构预测指标和 FLAb 预测指标合并为综合分：

```text
Total Score =
  0.45 * Binding / Interface Score
+ 0.20 * Expression Score
+ 0.15 * Aggregation Safety Score
+ 0.10 * Thermostability Score
+ 0.10 * Novelty / Diversity Score
```

这个权重不必完全等于比赛权重，因为比赛中的 SPR 是湿实验结果，而计算阶段只能做代理预测。但表达和聚集应该明确纳入排序。

## 11. 使用注意事项

1. FLAb 是多来源数据，实验体系和单位并不统一，不能把所有 CSV 直接混在一起训练。

2. 不同数据集的 `fitness` 方向不同，必须检查 `Direction of favorable values`。

3. binding 数据的抗原不同，不能直接等同于 Nipah G 蛋白亲和力。

4. 一些数据是高通量预测值或展示系统读数，不一定等同于真实 SPR Kd。

5. VHH、Fv、scFv、Fab、IgG 的实验体系不同，训练时最好分类型处理。

6. 某些数据集只有 heavy，没有 light，这通常表示 VHH、纳米抗体或单链数据，不能强行当成完整 Fv。

7. `jain2024assessment_*` 和 `kirby2024retrospective_*` 等数据集存在非标准 fitness 字段，官方 README 提到这些数据可能被排除在自动打分之外。

8. 许可证不完全相同。如果用于公开提交或商业化，需要查看 `data/flab_metadata.csv` 和各论文许可证。

## 12. 简短结论

FLAb 是一个非常适合作为抗体 AI 项目“评价和筛选底座”的数据库。它不能直接替代 RFdiffusion、ProteinMPNN、AlphaFold/Boltz/Chai 等生成和结构预测工具，但可以补上抗体设计中最容易被忽视的一环：候选抗体是否容易表达、是否容易聚集、是否具有较好的可开发性。

在 Bio-OS 抗体设计赛题中，推荐把 FLAb 用作候选抗体的 developability 预测训练集和 benchmark，而不是把它当成 Nipah 专属抗体数据集。最实际的策略是：用生成模型负责提出候选，用结构模型评估结合，用 FLAb 训练或校准表达、聚集、稳定性和多反应性过滤器，最后综合排序选择 6 条提交。
