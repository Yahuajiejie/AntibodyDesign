# noise_floor_tree 实验报告：能留下多少样本？

日期：2026-06-21
状态：分析完成，待重新接入 `pairs.py`/`config.py`（当前 `noise_floor_tree.py` 是孤立文件，未接入主流程）

## 1. 问题回顾

`randomized_bst`/`balanced_tree` 在 `add_redundancy_edges=False` 时，叶子边只连"排序后下标相邻"的记录。这个规则在样本密集的组里会选出大量标签差极小、近似噪声的比较对。

实测到的最严重案例：`AbRank/dataset/SARS_CoV_2/neg_log10_kd_M/experimental` 组，72,117 条记录，标签跨度 8.513（4.455~12.968），plain backbone 的 53,672 条边里，中位标签差只有 **0.00015**。

这一组 99.6% 的记录来自 Engelhart et al. (*Scientific Data*, 2022) 发布的 AlphaSeq SARS-CoV-2 抗体数据集——用酵母展示+测序反推 Kd，论文自己报告的三次技术重复间 Pearson 相关系数是 0.66~0.93，换算下来同一个样本重复测量的标准差大约在 0.5~1.0(log10 单位)。也就是说，现在选出来比较的"邻居对"，标签差比这个 assay 自己的测量噪声还小 2000~5000 倍——这些比较对本身就分不出谁大谁小。

## 2. 修法：noise_floor_tree

不丢记录、不平滑标签，只改"跟谁比"：

1. 按 `rank_label` 排序后，单次扫描把记录聚成簇——簇内任意两点的标签差不超过噪声下限 τ。
2. 每个簇取中位数位置的记录当代表，在代表之间跑现成的 median-split 树（`tree._build_tree_edges`），可选加冗余边。
3. 簇内其余记录（非代表），各连一条边到**相邻簇**（前一个簇或后一个簇）里更近的那个代表——由于簇间天然有 >τ 的间隔，这条边保证标签差大于 τ。

详细设计和正确性证明见 `affinity_transformer/dataset/pair_sampling/noise_floor_tree.py` 的模块 docstring。

## 3. 分析中发现的 bug：单链聚类的"串联"问题

第一版聚类规则是"和**上一个**点的间距超过 τ 才分簇"（标准单链聚类）。这个规则在样本密集、近似连续分布的组里会出问题：只要存在一条由小步子连成的链，整条链会被串成一个簇，跟簇两端点实际差多少没关系。

实测验证（SARS_CoV_2 组，τ=0.3）：

| τ | 簇数 m（旧规则） | 簇数 m（修正后） |
| - | - | - |
| 0.0 | 48,614 | 48,614 |
| 0.05 | 9 | 156 |
| 0.1 | 5 | 80 |
| 0.3 | **1**（串成一整团） | 29 |
| 0.5 | **1** | 17 |
| 1.0 | **1** | 9 |

τ=0.3~1.0 这个我们想用的区间，旧规则直接把整个 7.2 万条记录的组串成一个簇——触发了"整组退化成单簇"的兜底分支，兜底分支等价于退回 plain backbone，而 plain backbone 又会因为标签并列被 `_emit_pair` 跳过，导致 **16,659 条记录(23%)完全没有训练边**，直接违反"不丢数据"的设计目标。

修法：把"和上一个点的间距"换成"和**本簇第一个点**的间距"（限制整簇的总跨度不超过 τ，不是只看相邻步长）。这是聚类里"单链 vs 限定跨度"的经典区别，改起来是一行逻辑的事，但结果完全不同。

## 4. 修正后的实测结果

### 4.1 SARS_CoV_2 超大组（用修正后的聚类规则）

| τ | 簇数 m | 压缩比 | 边数 | 缺失记录数 | 中位标签差 | 标签差<0.0002 占比 |
| - | - | - | - | - | - | - |
| plain backbone（无聚类） | — | — | 53,672 | 18,445 | 0.00015 | 58.6% |
| 0.0 | 48,614 | 1.5x | 72,116 | **0** | 0.0001 | 68.1% |
| 0.05 | 156 | 462x | 72,116 | **0** | 0.0375 | 0.0% |
| 0.1 | 80 | 902x | 72,116 | **0** | 0.0752 | 0.0% |
| **0.3** | 29 | 2487x | 72,116 | **0** | **0.223** | 0.0% |
| 0.5 | 17 | 4242x | 72,116 | **0** | 0.367 | 0.0% |
| 1.0 | 9 | 8013x | 72,116 | **0** | 0.690 | 0.0% |

边数始终是 n-1=72,116（每条记录恰好出现在一条边里），不随 τ 变化——这就是"不丢数据"的字面意思：72,117 条记录一条不少，只是每条边连的对象从"下标相邻"换成了"标签差过得了 τ 这道关"的对象。τ=0.3 时中位标签差从 0.00015 提升到 0.223，提升约 **1500 倍**；标签差小于 0.0002 的比例从 58.6% 降到 0%。

### 4.2 全量数据集（仅本地能拿到的 AbRank 子集，133,490 条可训练记录）

| τ | 总边数 | 总记录数 | 有边覆盖的记录数 | 中位标签差 | 标签差<0.0002 占比 |
| - | - | - | - | - | - |
| 0.0 | 129,425 | 133,490 | 133,490（100%） | 0.00069 | 37.9% |
| **0.3** | 129,418 | 133,490 | 133,483（99.995%） | **0.246** | **0.0%** |
| 0.5 | 129,415 | 133,490 | 133,481（99.992%） | 0.396 | 0.0% |

**直接回答"能留下来多少样本"：τ=0.3 时 133,483/133,490 条记录都还在训练集里，只丢了 7 条（0.005%），总边数几乎不变(129,425 → 129,418，少了 7 条，跟丢的记录数对得上)。** 中位标签差从 0.00069 提升到 0.246，约 350 倍；几乎从数据集里彻底消灭了"标签差小于 0.0002"这类零信号比较对(37.9% → 0%)。

那 7 条没覆盖到的记录，是极少数规模很小的组(n=2~3)在"全组退化成单簇"兜底分支里恰好撞上标签并列被跳过——是个真实存在但影响极小的残留问题，接下来正式接入代码时需要单独处理(比如对这种小组直接禁用兜底逻辑，改成强制连一条边，哪怕标签是并列的也好于完全不出现)。

## 5. 推荐配置

- τ = 0.3（log10 单位，对应 `neg_log10_kd_M` 这一类指标），依据是 AlphaSeq 论文自报的重复性数据，比估算出的重复间噪声标准差(0.5~1.0)还留了余量,偏保守。
- 这是当前唯一查到测量误差来源的指标(`AlphaSeq`/SARS_CoV_2 Kd)。数据集里其余来源(`RBD-escape`、`AbCoV`、各种 HIV panel)如果要分别定 τ，需要再去查各自的可重复性报告——现在用同一个全局 τ 是简化处理，对其他本来就稀疏的小组基本不影响(因为它们的真实间距通常已经超过 0.3，聚类规则相当于空操作)。

## 6. 局限 / 还没做的事

1. 本地沙箱只能访问到 AbRank 这一份原始数据(`processed/binding/AbRank/dataset/records.parquet`)，拿不到 `g00_max_antigen_context` 这个正式训练用的多来源合并 split——上面"全量数据集"那张表只覆盖 AbRank 子集，不是最终训练集的真实大小，但聚类失效的机制和修法是通用的，不依赖具体是哪个数据源。
2. `noise_floor_tree.py` 目前是孤立文件，`_cluster_by_noise_floor` 还是本报告里指出有 bug 的单链版本，没有接入 `pairs.py`/`__init__.py`/`validation.py`/`config.py`。下一步要做的是：把 `_cluster_by_noise_floor` 换成本报告验证过的"限定总跨度"版本，再重新走一遍接入流程，并补单测（边的标签差必须 > τ、记录不丢失、退化情况的兜底也不能丢记录、确定性、τ 校验）。
3. τ=0.3 这个值只对 SARS_CoV_2/AlphaSeq 这一个指标来源有实证依据，不是全局意义上"最优"的值，调到正式训练前建议先跑一次小规模训练对比，而不是直接信这份纯统计分析。
