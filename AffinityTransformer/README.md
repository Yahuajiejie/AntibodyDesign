# 抗体-抗原亲和力排序模型项目介绍

## 1. 项目背景

抗体药物发现的早期阶段通常需要在大量候选抗体序列中筛选出更有潜力的分子。湿实验能够直接测定抗体与抗原之间的结合能力，但实验成本高、周期长，难以覆盖大规模候选空间。因此，在进入实验验证之前，利用计算模型对候选抗体进行预筛选，是抗体设计流程中具有实际价值的一环。

本项目面向第四届 Bio-OS AI 开源大赛初赛任务，目标是根据给定的抗原信息和一组候选抗体序列，预测这些抗体在同一抗原背景下的相对亲和力强弱，并输出排序结果。模型的最终表现由 Spearman 等级相关系数评价，即关注预测排序与真实实验排序之间的一致程度。

与直接预测某个抗体的绝对 Kd、IC50 或 EC50 数值相比，本项目更关心“哪些候选分子更值得进入后续验证”。在候选序列数量较大、实验数据来源复杂且存在批次差异时，可靠的相对排序往往比单个数值的精确回归更有实际意义。

## 2. 问题定义：从亲和力回归到排序学习

抗体-抗原亲和力预测常被理解为回归问题，即输入抗体和抗原序列，输出一个连续的结合强度数值。然而，本任务中的数据来自不同研究和实验体系，标签可能是平衡解离常数 Kd、半抑制浓度 IC50、半效应浓度 EC50，也可能是 fitness、log-ratio 或 neg-log-Kd 等派生指标。

这些指标并不具有统一的物理意义和量纲。即使它们都与结合能力或功能活性有关，也不能在全局范围内直接横向比较。不同实验平台之间还可能存在系统性偏移。如果将所有记录强行合并为一个绝对数值回归任务，模型很容易学习数据来源和标签尺度，而不是抗体与抗原之间真正可迁移的匹配关系。

因此，本项目将主要建模目标设为组内排序。模型为每个抗体-抗原组合输出一个实数分数，这个分数不要求具有明确物理单位，只用于同一可比实验背景内的相对比较。训练和评估均围绕“候选抗体的顺序是否正确”展开。

排序模型的评估需要同时说明抗原和抗体是否在训练阶段出现过。由此可以得到四种不同的泛化条件。

| 抗原 | 抗体 | 对应问题 |
| --- | --- | --- |
| 已见 | 已见 | 已见实体之间的比较补全 |
| 已见 | 未见 | 已知抗原上的新抗体排序 |
| 未见 | 已见 | 未见抗原上的已知抗体排序 |
| 未见 | 未见 | 未见抗原与新抗体排序 |

四种条件回答的问题不同，不能仅用“验证集没有重复 pair”概括，也不应合并为一个总分。

### 2.1 已见实体之间的比较补全

训练集和验证集可以共享抗原与抗体，只要求完整的比较对不重复。验证样本形如：

\[
(\text{antigen}, \text{antibody}_i, \text{antibody}_j)
\]

且这一完整三元关系未出现在训练集中。

这种划分测试的是模型能否补全已见实体之间尚未使用的比较关系。它适合作为 pairwise 训练流程和排序损失的基本检查，但不能说明模型能够处理新抗体或新抗原。

### 2.2 已知抗原上的新抗体排序

训练集和验证集可以共享抗原，但验证抗体及其近似序列簇不能在训练集中出现。该设置测试的是：

> 在模型已经见过某个抗原及其部分实验数据后，能否对该抗原下的新候选抗体进行排序？

这对应已知靶点上的后续筛选和抗体优化场景。

### 2.3 未见抗原上的已知抗体排序

验证集中的抗原簇不能在训练集中出现，但抗体或抗体簇可以在其他训练抗原中出现。该设置测试的是：

> 当抗体表征本身已有训练经验时，模型能否把抗体-抗原匹配规律迁移到一个新抗原？

这一协议将“抗原冷启动”与“抗体冷启动”分开，有助于判断跨抗原性能下降究竟来自抗原表征，还是来自同时更换抗体候选集合。

### 2.4 未见抗原与新抗体排序

验证集中的抗原簇和抗体簇都不允许在训练集中出现。该设置测试的是：

> 面对训练阶段没有见过的目标抗原，模型能否对一批新的候选抗体进行排序？

比赛后续需要针对新公布的目标抗原设计并筛选新抗体，因此本项目将这一设置作为主要的模型选择协议。已知抗原上的新抗体排序和未见抗原上的已知抗体排序作为辅助分析，比较对补全主要用于排查训练和实现问题。

除上述四种实体泛化条件外，项目还保留原始的 group holdout 作为工程基线。group holdout 隔离的是 `group_id`，而 `group_id` 同时包含抗原、指标、实验方法或数据来源等可比性信息，因此其含义取决于具体分组规则。它可以表示“未见同质实验组”，但不能自动解释为“未见抗原”。

## 3. 数据特点与主要挑战

本项目使用的数据包含多个来源的抗体-抗原记录，既有序列数据，也有结构数据库和纳米抗体相关数据。数据处理阶段主要面对以下问题。

第一，实验指标异构。不同记录可能使用 Kd、IC50、EC50、fitness 等标签，它们的方向、单位和实验含义并不完全一致，不能直接作为同一回归目标使用。

第二，样本之间的可比性有限。只有在相同或相近的抗原背景、实验方法和指标体系下，抗体之间的相对排序才具有明确意义。跨抗原、跨实验平台或跨指标直接构造排序关系，会引入错误监督。

第三，抗原信息不完整。部分记录只提供抗体序列，缺少精确的抗原氨基酸序列或结构背景，而抗原信息又是判断亲和力的必要上下文。

第四，抗体形态存在差异。传统 Fv 抗体通常包含 VH 与 VL 两条可变区链，VHH 则只有单条重链可变区。模型需要在统一框架下处理这两类输入。

第五，pair 不是独立原始样本。同一条抗体-抗原记录可以参与多个训练 pair，如果先生成 pair 再随机切分，同一 record 很容易同时进入训练集和验证集。此时即使完整 pair 不重复，也可能高估模型的泛化能力。

围绕这些问题，项目的数据处理流程包括：实体规范化、同质分组、标签方向统一、抗原特征补全、抗体序列标准化、record 级切分，以及切分后的排序样本构造。

## 4. 同质分组：决定哪些记录可以比较

排序学习的前提是样本之间具有可比性。并不是任意两个抗体都可以直接组成训练样本对。只有当它们对应相同或高度一致的抗原背景，并且使用相同类型的实验指标和足够接近的实验条件进行测量时，二者的亲和力高低才具有可靠意义。

项目根据抗原名称或抗原标识、指标类型、实验方法和数据来源等信息生成 `group_id`。pairwise 和 listwise 训练样本只在同一 group 内构造，不跨组建立排序关系。这样可以避免将不同实验体系中的数值差异误认为真实的亲和力差异。

需要区分 `group_id` 和数据切分所使用的实体键：

- `group_id` 决定哪些记录能够互相比较；
- split key 决定验证时哪些信息必须对模型保持未见。

同一个抗原可能因为指标、实验方法或数据来源不同而形成多个 group。因此，group holdout 并不自动等同于未见抗原测试。相反，在“已知抗原上的新抗体”协议中，同一 group 可以包含训练 records 和验证 records，但 pair 必须在切分完成后分别构造，不能跨 split 连接。

## 5. 数据切分：先确定泛化对象，再划分 records

除 pair holdout 外，正式泛化协议都以原始 record 为起点。标准流程为：

```text
原始 records
→ 规范化抗原和抗体实体
→ 建立序列簇与测量家族
→ 按评估协议划分 train / valid / test
→ 在各 split 内独立生成 pointwise、pairwise 或 listwise 样本
```

Pair holdout 是一个有意保留的例外：它直接对规范化后的 unique pairs 划分，用于测试已见实体之间的关系补全，因此允许同一 record 同时参与训练 pair 和验证 pair。该协议必须明确标记为 transductive diagnostic，不能与其余实体级泛化协议混为一谈。

为了识别不同形式的重复和近重复，数据表需要维护以下信息：

- `record_id`：原始记录标识；
- `measurement_family_id`：同一生物样本或技术重复的归属；
- `antibody_sequence_key`：标准化后的抗体序列键；
- `antibody_cluster_id`：抗体序列簇；
- `antigen_sequence_key`：标准化后的抗原序列键；
- `antigen_cluster_id`：抗原序列簇；
- `interaction_key`：抗原与抗体组合；
- `group_id`：排序可比性分组。

### 5.1 Pair holdout

Pair holdout 只要求规范化后的完整比较对不跨 split：

```text
(antigen_key, min(antibody_i, antibody_j), max(antibody_i, antibody_j))
```

抗原、抗体、record 和 measurement family 都可以在训练 pair 与验证 pair 中重复。该协议只适用于 pairwise 训练的诊断，不用于宣称新抗体或新抗原泛化。

### 5.2 Group holdout

Group holdout 以 `group_id` 为切分单位，同一个 group 的 records 只能出现在一个 split 中。随后在各 split 内分别生成训练样本。

该协议保证：

- `group_id` 不跨 split；
- 同一 group 内生成的 pair 不跨 split。

但它不保证：

- 同一抗原不跨 split；
- 同一抗体不跨 split；
- 同一抗原的不同 assay、metric 或 study group 不跨 split；
- 同一抗体-抗原 interaction 不跨 split。

因此，`GROUP_HOLDOUT_SPLIT` 适合作为原始实现的对照基线，也可以测试模型对未见同质实验组的迁移能力，但不能在没有额外审计的情况下解释为 unseen-antigen split。

### 5.3 Within-antigen antibody holdout

该协议允许抗原在训练集和验证集中重复，但要求：

- `record_id` 不重叠；
- `measurement_family_id` 不重叠；
- `interaction_key` 不重叠；
- `antibody_sequence_key` 不重叠；
- `antibody_cluster_id` 不重叠。

验证集中的抗体应当是模型在任何训练抗原上都没有见过的新抗体簇，而不只是当前抗原下的新组合。

### 5.4 Antigen cluster holdout

该协议以 `antigen_cluster_id` 为切分单位。同一抗原簇对应的所有 records 和所有 `group_id` 必须进入同一个 split。

要求：

- `antigen_sequence_key` 不跨 split；
- `antigen_cluster_id` 不跨 split；
- 同一抗原簇下的不同 assay、metric 和 study group 不跨 split；
- `interaction_key` 不跨 split。

抗体序列或抗体簇可以在训练集和验证集中重复。该协议用于单独测试抗原冷启动，即模型面对新抗原时，能否利用已经学到的抗体表示和交互规律完成排序。

### 5.5 Dual cold-start split

主验证协议同时隔离：

- `antigen_cluster_id`；
- `antibody_cluster_id`；
- `interaction_key`；
- 测量重复及其派生记录。

同一抗原的不同 assay、metric 或 study group 应当随抗原簇一起进入同一个 split。抗体序列簇也不能同时出现在训练集和验证集。

### 5.6 五种协议的关系

| 协议 | 抗原可重叠 | 抗体簇可重叠 | `group_id` 可重叠 | 主要用途 |
| --- | --- | --- | --- | --- |
| Pair holdout | 是 | 是 | 是 | 已见实体间的比较补全 |
| Group holdout | 可能 | 可能 | 否 | 未见同质实验组的工程基线 |
| Within-antigen antibody holdout | 是 | 否 | 可以 | 已知抗原上的新抗体 |
| Antigen cluster holdout | 否 | 是 | 通常否 | 新抗原、已知抗体 |
| Dual cold-start | 否 | 否 | 通常否 | 新抗原与新抗体 |

其中，Pair、Within-antigen、Antigen-cluster 和 Dual cold-start 构成“抗原是否已见 × 抗体是否已见”的四种实体泛化条件。Group holdout 与这一矩阵正交，它隔离的是实验可比性分组，应当作为单独基线解释。

### 5.7 切分审计

每次切分后都应输出实体重叠报告，包括：

- exact record overlap；
- measurement family overlap；
- exact antibody sequence overlap；
- antibody cluster overlap；
- exact antigen sequence overlap；
- antigen cluster overlap；
- interaction overlap；
- group overlap；
- study、assay 和 metric 的分布差异。

不同协议允许的重叠不同。例如 within-antigen 协议中抗原重叠是预期行为，antigen cluster holdout 中抗体重叠可以被允许，而 dual cold-start 中抗原簇与抗体簇重叠都必须为零。审计结果需要按照协议解释，不能只给出笼统的“是否泄露”。

## 6. 标签方向统一：让“分数越大越好”

在完成分组后，不同指标仍需要统一方向。对于 Kd、IC50、EC50 等指标，通常数值越小表示结合越强或功能效应越明显；对于 fitness、neg-log-Kd 等指标，可能本身就是数值越大越好。如果不处理方向差异，模型会接收到相互矛盾的监督信号。

项目将所有可用于排序的标签转换为统一的正向排序目标：数值越大，表示相对亲和力或活性越强。对于“小值更优”的指标，可以通过取负值、取负对数或按照字段定义进行方向反转；对于本身已经是正向含义的指标，则保持原方向。比值或相对变化类标签需要结合具体实验定义判断极性。

方向统一只保证排序语义一致，并不意味着不同指标可以跨 group 直接比较。

## 7. 抗原表征：Exact 与 MSA 的双路径设计

抗原信息是亲和力排序中的关键上下文。一个抗体的结合能力并不是由抗体序列单独决定的，而是取决于它与特定抗原之间的匹配关系。考虑到数据中存在抗原序列缺失或描述不完整的问题，本项目设计了双路径抗原表征方案。

第一条路径是精确序列路径（Exact Path）。该路径根据 UniProt ID、抗原名称、突变株信息或其他外部标识，检索与实验记录对应的具体抗原序列。精确序列有助于捕捉突变位点、局部氨基酸变化以及可能影响表位识别的细粒度差异。

第二条路径是同源序列比对路径（MSA Path）。当精确抗原序列难以确认，或希望引入更广泛的进化背景时，可以基于同源序列构建多序列比对。MSA 表征能够反映抗原家族中的保守区域和变异区域，为模型补充进化约束。

两条路径提供的信息并不相同。Exact Path 回答“当前实验中的具体抗原是什么”，MSA Path 则描述“这个抗原所属家族中哪些位置更保守”。在亲和力排序任务中，精确序列承担主要区分作用，MSA 作为家族背景的补充。

项目设置三类抗原表征方案用于比较：

| 方案 | 抗原输入 | 编码方式 | 主要作用 |
| --- | --- | --- | --- |
| Exact-Only | 精确抗原序列 | ESM-2 编码后池化 | 捕捉具体抗原和突变差异 |
| MSA-Only | 同源序列比对矩阵 | ESM-MSA 编码后聚合 | 捕捉进化约束和家族背景 |
| Exact + MSA | 精确序列与 MSA 双路输入 | 两路编码后融合 | 同时利用单点差异和进化背景 |

MSA 也可能使同一家族中的多个突变株表征过于接近，因此 MSA-Only 不被预设为最优方案，其实际贡献需要通过消融实验判断。

## 8. 缺失信息处理：显式标记，而不是伪造特征

真实数据中并不总能同时获得精确抗原序列和高质量 MSA。为了让模型在信息不完整时仍能运行，需要稳定的降级策略。

如果某一路抗原表征无法获得，可以使用占位向量维持张量形状，但必须同时提供显式 mask。尤其在注意力计算中，缺失路径不能作为有效 token 参与权重归一化，否则占位向量会干扰有效特征的聚合。

融合模块同时接收特征和有效性标记。有效路径参与编码，无效路径只用于维持批处理结构。这样既保证工程稳定性，也避免模型把缺失值当作真实生物学信号。

## 9. 抗体表征：兼容 Fv 与 VHH 的统一编码

传统 Fv 抗体通常由 VH 与 VL 两部分组成，VHH 则只有单条重链可变区。为了在统一模型中处理两类输入，项目使用显式类型标记和固定链顺序。

对于 Fv，模型按固定顺序组织 VH 和 VL，并加入抗体类型及链边界标记。对于 VHH，则使用 VHH 类型标记和单链表示。这样可以帮助编码器区分不同的抗体输入形式，同时避免把填充区域误当作有效序列。

抗体编码器将比较通用蛋白语言模型和抗体专用语言模型。ESM-2 提供通用蛋白序列表征，AbLang-2 等模型则可能更适合捕捉 CDR 多样性和框架区保守性。二者的优劣通过相同切分和训练条件下的实验确定。

## 10. 模型架构：编码、交互与排序打分

模型由抗原编码器、抗体编码器、抗体-抗原交互模块和打分头组成。

抗原编码器将 Exact Path 和 MSA Path 中的信息转换为残基级或序列级表示；抗体编码器将 VH/VL 或 VHH 序列转换为相应特征。两侧表示随后进入交互模块。

项目使用交叉注意力学习抗体与抗原之间的条件依赖。这里的交叉注意力不是三维结构模拟，而是一种特征交互方式：模型可以在抗原上下文下重新加权抗体残基，也可以在抗体上下文下关注抗原侧更相关的位置。

交互后的变长表示通过 Attention Pooling 聚合为固定维度向量，再由打分头输出一个实数分数。该分数只表示当前抗原背景下候选抗体的相对优先级。

## 11. 训练目标

项目支持 pointwise、pairwise 和 listwise 三类训练方式，它们共享相同的 record 切分和模型编码框架。

### 11.1 Pointwise

Pointwise 训练直接使用单条 record 的标签监督模型输出。它实现简单，也能利用全部 records，但需要额外处理不同 group 之间的标签尺度差异。

### 11.2 Pairwise RankNet

Pairwise 训练在同一 group 内抽取两个 records，并要求模型输出分数差与真实排序方向一致。设模型对样本 \(i,j\) 的输出为 \(s_i,s_j\)，则：

\[
P_{ij}
=
\frac{1}{1+\exp[-\sigma(s_i-s_j)]}
\]

如果真实标签显示 \(i\) 优于 \(j\)，目标方向为 1；反之为 0。Pairwise 训练不要求拟合跨实验体系的绝对数值，是当前项目的主要训练方案。

### 11.3 Listwise

Listwise 训练直接在一个 group 或 group 子列表上优化整体顺序。它能显式利用组内全局排序结构，但对 batch 组织、超大 group 采样和显存控制提出了更高要求。

三种任务头使用相同的最终 Spearman 指标评估。比较时保持原始 records、split 和计算预算尽量一致，避免将数据量差异误认为任务头本身的优势。

## 12. Pair 构造与采样

同一 group 包含 \(n\) 条记录时，全部候选 pair 数量为：

\[
\binom{n}{2}=O(n^2)
\]

大 group 无法枚举所有 pair。固定比例抽样也可能造成大量 records 长期不被覆盖。项目因此需要同时考虑 pair 数量、record coverage、标签差和测量噪声。

当前采样实验包括分块采样、随机树采样以及噪声感知的多尺度采样。采样器只在 split 内部运行，不跨 train、validation 或 test 生成 pair。比较不同采样算法时，需要同时报告：

- pair 数量；
- record coverage；
- 标签差分布；
- 节点 degree 分布；
- 构造时间和内存；
- pairwise accuracy 与 signed margin；
- 最终 group-level Spearman。

## 13. 评估与消融实验设计

项目以 group-level Spearman 为主要评价指标，并分别计算 macro Spearman 与按 group 大小加权的 weighted Spearman。不同切分协议的结果分别报告：

- pair holdout；
- group holdout；
- within-antigen antibody holdout；
- antigen cluster holdout；
- dual cold-start。

模型开发过程中，pair holdout 用于检查 pairwise 训练是否正常；group holdout 保留为原始工程基线；within-antigen 用于判断新抗体泛化；antigen cluster holdout 用于单独判断抗原冷启动；最终模型选择主要参考 dual cold-start 验证结果。

除了总体指标，还需要报告不同抗原、不同 assay、不同 metric、不同 group 大小和不同抗原信息完整度下的表现。这样可以避免少数超大 group 掩盖其他数据上的失效。

主要消融方向包括：

| 消融方向 | 对比内容 | 目的 |
| --- | --- | --- |
| 切分协议 | Pair / Group / Within-antigen / Antigen-cluster / Dual cold-start | 区分关系补全、实验组迁移、抗体冷启动、抗原冷启动与双重冷启动 |
| 任务头 | Pointwise / Pairwise / Listwise | 判断不同排序监督形式的适用范围 |
| Pair 采样 | 分块 / 随机树 / 噪声感知多尺度 | 比较覆盖、可靠性和计算规模 |
| 抗原表征 | Exact-Only / MSA-Only / Exact+MSA | 判断精确序列与进化背景的贡献 |
| 抗体编码器 | ESM-2 / AbLang-2 | 比较通用蛋白模型与抗体专用模型 |
| 交互模块 | 简单拼接 / Cross-Attention | 判断显式条件交互是否有效 |
| 池化方式 | Mean Pooling / Attention Pooling | 判断可学习池化是否适合变长输入 |
| 缺失处理 | 无 mask / 显式 mask | 检查缺失路径是否干扰模型 |

这些实验不做完整笛卡尔积。项目先固定一个可靠基线，每次只改变一个主要因素，再对最佳配置进行多随机种子复验。

## 14. 项目特点

本项目不把亲和力预测简单处理为全局回归，而是在可比实验背景内学习候选抗体的相对顺序。数据处理、训练样本构造和 Spearman 评估围绕同一排序目标组织。

同质分组和数据切分承担不同职责。前者保证标签可比，后者定义模型需要泛化到的新实体。通过 pair holdout、group holdout、已知抗原新抗体、antigen cluster holdout 和 dual cold-start，可以分别检查关系补全、同质实验组迁移、抗体冷启动、抗原冷启动和双重冷启动。

抗原侧同时保留精确序列与 MSA 两条路径，抗体侧兼容 Fv 和 VHH，并支持通用蛋白模型与抗体专用模型。模型交互、任务头和 pair 采样均可以在同一数据框架下独立比较。

## 15. 当前边界与后续方向

本项目目前主要聚焦序列层面的抗体-抗原亲和力排序。交叉注意力用于学习序列特征之间的统计依赖，不替代真实分子对接或结构动力学模拟。结构分支作为独立模型路线进行比较，不把预测单体结构直接解释为真实抗体-抗原界面。

当前工作的重点是完成严格的数据切分审计、噪声感知的 pair 采样、三类任务头比较，以及序列和结构模型的受控实验。后续可以进一步完善 assay-specific 不确定性建模，并分析不同模型在关系补全、新抗体泛化和跨抗原迁移之间的性能差距。

本项目希望最终形成一个可复现的抗体候选排序框架：既能处理来源异构、规模不均衡的亲和力数据，也能明确说明模型在什么条件下有效、在什么条件下仍然缺乏泛化能力。
