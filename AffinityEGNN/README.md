# 抗体-抗原亲和力排序模型项目介绍（AffinityEGNN）

## 1. 项目背景

抗体药物发现的早期阶段通常需要在大量候选抗体序列中筛选出更有潜力的分子。湿实验能够直接测定抗体与抗原之间的结合能力，但实验成本高、周期长，难以覆盖大规模候选空间。因此，在进入实验验证之前，利用计算模型对候选抗体进行预筛选，是抗体设计流程中具有实际价值的一环。

本项目面向第四届 Bio-OS AI 开源大赛初赛任务，目标是根据给定的抗原信息和一组候选抗体序列，预测这些抗体在同一抗原背景下的相对亲和力强弱，并输出排序结果。模型的最终表现由 Spearman 等级相关系数评价，即关注预测排序与真实实验排序之间的一致程度。

AffinityEGNN 是与 AffinityTransformer 并行开展的对照分支。AffinityTransformer 专注于序列层面的特征学习，AffinityEGNN 则探索将三维结构信息引入编码器的可行路径，并系统比较多种结构感知编码方案的实际效果。两个项目共享相同的数据处理流程、同质分组策略、pair 采样器和 RankNet 训练目标，差异集中于 `antibody_encoder` 和 `antigen_encoder` 的实现。

## 2. 问题定义：从亲和力回归到排序学习

抗体-抗原亲和力预测常被直观地理解为回归问题，即输入抗体和抗原序列，输出一个连续的结合强度数值。然而，本任务中的数据来源较为异构，不同数据集可能采用不同的实验体系和测量指标，例如平衡解离常数 Kd、半抑制浓度 IC50、半效应浓度 EC50，以及部分数据集中出现的 fitness 或 log-ratio 类指标。

这些指标并不总是具有相同的物理意义和量纲。如果将这些数据强行混合为一个统一的回归目标，模型很容易学习到数据集来源、测量条件或标签尺度差异，而不是真正与抗体-抗原相互作用相关的信号。

因此，本项目将建模目标从"预测绝对数值"调整为"学习相对顺序"：模型不要求输出具有明确物理单位的亲和力常数，而是为每个抗体-抗原组合生成一个相对得分，仅在同一抗原、同一指标体系下具有比较意义。通过这种方式，模型能够更自然地对齐 Spearman 排序评价指标，也能降低跨数据集尺度差异对训练过程的干扰。

## 3. 数据特点与主要挑战

本项目使用的数据包含多个来源的抗体-抗原记录，既有结构数据库相关信息，也有序列库和纳米抗体数据。整体来看，数据预处理阶段需要解决五类核心问题。

第一，实验指标异构。不同记录可能使用 Kd、IC50、EC50、fitness 等不同标签，方向、单位和实验含义并不完全一致，不能直接作为同一回归目标使用。

第二，样本之间的可比性有限。只有在相同或相近的抗原背景、实验方法和指标体系下，抗体之间的相对排序才具有明确意义。

第三，抗原信息不完整。部分记录只提供抗体序列，缺少精确的抗原氨基酸序列或结构背景。

第四，抗体形态存在差异。传统 Fv 抗体通常包含 VH 与 VL 两条可变区链，而纳米抗体 VHH 只包含单条重链可变区，模型需要在统一框架下处理不同抗体类型。

第五，**结构数据稀缺**（AffinityEGNN 特有挑战）。比赛提供的结构数据来自 SAbDab（Structural Antibody Database，牛津大学 OPIG 维护）的 2026 年 3 月快照，包含约 10,517 个抗体-抗原复合物 PDB 文件。然而其中仅约 735 个 PDB（约 6%）附有亲和力标注，且同一抗原下有多个可比抗体的分组极少（≥5 个抗体的分组仅 49 个，最大可构建的训练 pair 数约 3,173 对）。与 binding 数据集中的百万级序列数据相比，相差 2～3 个数量级。这意味着 AffinityEGNN **无法仅靠 SAbDab 自带亲和力标注来训练有竞争力的排序模型**，必须设计兼容大规模序列亲和力数据的结构引入策略。

## 4. 同质分组：保证排序关系可比较

排序学习的前提是样本之间具有可比性。并不是任意两个抗体都可以直接组成训练样本对——只有当它们对应相同或高度一致的抗原背景，并且使用相同类型的实验指标进行测量时，二者的亲和力高低才具有可靠的比较意义。

因此，项目在数据处理阶段引入同质分组策略。每条记录会根据抗原名称或抗原标识、指标类型、实验方法等信息生成分组标签。模型训练时只在同一分组内部构造成对比较关系，不跨组生成 pair。这一策略的核心思想是：模型不需要在全局范围内判断"某个 Kd 数值是否一定优于某个 IC50 数值"，而是需要在局部可比环境中学习"同一抗原背景下哪个抗体更优"。

## 5. 标签方向统一：让"分数越大越好"

在完成分组后，不同指标仍需要统一方向。对于 Kd、IC50、EC50 等指标，通常数值越小表示结合越强；而对于 fitness、neg_log_kd 等指标，可能本身就是数值越大越好。

项目将所有可用于排序的标签转换为统一的正向排序目标：数值越大，表示相对亲和力或活性越强。经过方向统一后，模型输出的相对得分能够与真实标签保持一致的排序语义，从而支持 Pairwise Ranking Loss 的训练。

## 6. 结构数据流程

AffinityEGNN 的核心工程任务是为 binding 数据集里的抗体和抗原提供三维结构，用于驱动结构感知编码器。由于 SAbDab 中有亲和力标注的结构数量远不足以覆盖训练需求，项目采用以下双轨策略：

**抗原结构获取（优先级由高到低）**

1. AlphaFold Database 直接下载：对 binding 数据集涉及的核心抗原（SARS-CoV-2 spike、VEGF、lysozyme、TNF、influenza HA 等），在 AF DB（https://alphafold.ebi.ac.uk）均有预计算结构可直接下载，通过 UniProt accession 检索，覆盖大多数已知蛋白质。
2. SAbDab 单体结构：对 SAbDab 中有实验结构的抗原（如已沉积的 spike、lysozyme 等），可提取抗原链单独使用，优先级高于 AF DB（实验结构精度更高）。
3. ESMFold 预测：对 AF DB 未覆盖、SAbDab 无实验结构的抗原，退而使用 ESMFold 进行单链结构预测（秒级，无需 MSA）。

**抗体结构获取**

训练数据中的抗体序列几乎没有对应的实验复合物结构，统一使用结构预测工具：

- IgFold：抗体专用结构预测，对 Fv 和 VHH 均有良好支持，预测速度秒级/条，CDR 区域精度优于通用模型（ESMFold）。
- ABodyBuilder2（ImmuneBuilder）：牛津 OPIG 出品，同样秒级，可作为 IgFold 的对照或替换。

两者均为 PyTorch 实现，支持批量推理，可为全部 binding 记录预处理好结构缓存（.pdb 文件），训练时直接读取，不在模型 forward 中调用结构预测。

**注意**：预测结构（尤其 CDR 区域）的精度有限。后续消融实验需验证预测结构引入的噪声对最终 Spearman 指标的影响，并与使用实验结构（SAbDab 覆盖的少量样本）的结果做对比。

## 7. 缺失信息处理：显式标记，而不是伪造特征

当某条记录无法获得有效结构（例如抗原序列未知导致无法预测结构，或结构预测失败），本项目的原则是：缺失信息可以被标记，但不能被伪造成真实生物学信号。

具体而言，如果某一路结构编码无法获得，可以在张量层面使用占位向量保持输入形状一致，但必须同时提供显式 mask，让模型知道该路径不可用。缺失路径不能作为有效 token 参与 attention 权重计算，否则全零向量可能干扰注意力分布，影响有效特征的聚合。

## 8. 五种技术方案

AffinityEGNN 定义了五种编码器方案，在共享的数据处理、pair 采样和 RankNet 训练框架下进行对照实验。五种方案的差异集中于 `antibody_encoder` 和 `antigen_encoder` 的实现，其余模块（cross-attention 交互、Attention Pooling、打分头）与 AffinityTransformer 保持一致。

各方案均满足 AffinityTransformer 的 encoder 接口约定：

```
forward(input_ids, attention_mask) -> FloatTensor[B, L, d_model]
```

或通过适配器层包装为该接口，以保证下游模块的可复用性。

---

### 方案 A：SaProt + Foldseek 结构 Token

**核心思路**：用 Foldseek 将三维结构编码为"结构字母序列"（20 类离散状态，描述局部空间构型），与氨基酸序列交织拼接（如 `AdEfGs...`），喂给 SaProt——一个在序列+结构 token 对上预训练的蛋白质语言模型。从模型架构看，与 AffinityTransformer 几乎完全相同，仅换了 tokenizer 和预训练权重。

**流程**：
```
抗体序列 → IgFold → .pdb → Foldseek → 结构 token
        \___氨基酸序列___/  → 拼接 → SaProt → [B, L, 480]

抗原序列 → AF DB 下载 .pdb → Foldseek → SaProt → [B, L, 480]
```

**接口适配**：SaProt 是 HuggingFace 格式，tokenizer 接受交织序列字符串，输出形状与 ESM-2 完全相同，可直接替换 AffinityTransformer 中的 `antibody_encoder` / `antigen_encoder`，下游代码零改动。

**关键依赖**：SaProt（Su et al., 2023）；Foldseek（van Kempen et al., 2023）

**优势**：实现成本最低；结构信息通过词表编码进语言模型，无需引入新的几何组件；批量 inference 速度与序列模型相当。

**劣势**：Foldseek 将连续几何信息量化为 20 类离散状态，损失精确的距离和角度信息；结构信息对模型的实际贡献难以与预训练本身的贡献解耦。

---

### 方案 B：GVP-GNN 几何等变编码器

**核心思路**：把蛋白质结构建为残基图（Cα 为节点，k-NN 或空间截断半径建边），用 GVP-GNN（Geometric Vector Perceptrons）在图上做等变消息传递。GVP 节点同时维护标量特征和向量特征，向量特征在 SE(3) 旋转下等变（即旋转坐标系时向量跟着旋转，标量不变），输出的标量特征作为残基 embedding 进入后续 cross-attention。

**图构建**：
```
节点：每个残基（Cα 坐标 + 氨基酸类型 embedding + 可选二级结构标签）
边：空间截断（≤ 10Å）或 k-NN（k=30）
边特征：残基间距离、单位方向向量（向量特征，SE(3)等变）
```

**流程**：
```
抗体结构（IgFold）→ 残基图 → GVP-GNN → [B, L, d_model]（标量部分）
抗原结构（AF DB） → 残基图 → GVP-GNN → [B, L, d_model]
                                        ↓（与AffinityTransformer一致）
                                  Cross-Attention → Attention Pooling → 打分头
```

**接口适配**：输入格式从 token ids 变为图数据（坐标 + 邻接信息），需要修改 `collate_fn`（`dataloader.py`）来处理坐标和边索引，并包装一层适配器使输出满足 `[B, L, d_model]` 格式。是五种方案中对 AffinityTransformer 基础代码改动最集中的部分。

**关键依赖**：GVP-GNN（Jing et al., NeurIPS 2020）；`torch_geometric`

**优势**：真正的 SE(3) 几何等变性，正确处理蛋白质结构在旋转/平移下的物理不变性；无需预训练，直接在亲和力任务上从结构特征学习；有成熟的开源实现（ProteinMPNN 的 encoder 即基于 GVP 思想）。

**劣势**：GVP-GNN 没有在大规模蛋白质结构数据上预训练，特征质量完全依赖下游 fine-tune；需要改动 collate 层，工程改动量比方案 A 大。

---

### 方案 C：EGNN 联合残基图（AffinityEGNN 名称的本义）

**核心思路**：将抗体和抗原的残基合并为一个联合图，加入跨分子边（界面区域 Ab-Ag 残基空间接触），用 EGNN（E(n) Equivariant Graph Neural Networks）做等变消息传递。节点特征 $h_i$ 和坐标 $x_i$ 同时更新，更新规则为：

$$m_{ij} = \phi_e(h_i,\ h_j,\ \|x_i - x_j\|^2)$$
$$x_i \leftarrow x_i + \sum_{j \in \mathcal{N}(i)} (x_i - x_j)\,\phi_x(m_{ij})$$
$$h_i \leftarrow \phi_h\!\left(h_i,\ \sum_{j \in \mathcal{N}(i)} m_{ij}\right)$$

消息传递之后，仅对抗体节点做图级池化，得到抗体的结构感知全局表征，直接送入打分头，不再需要独立的 cross-attention 模块（跨分子边的消息传递本身承担了抗体-抗原交互的建模）。

**联合图构建**：
```
节点：Ab 所有残基 ∪ Ag 所有残基（链标记区分来源）
边类型：
  - Ab 内部边（Cα 距离 ≤ 10Å）
  - Ag 内部边（Cα 距离 ≤ 10Å）
  - Ab-Ag 跨分子边（需要抗体和抗原的相对空间位置）
边特征：距离标量 + 方向向量（E(3) 等变）
```

**关键约束**：跨分子边的构建需要知道抗体和抗原在空间中的相对位置，即需要**复合物结构**（或对接结果）。若只有单体结构，跨分子边无法可靠构建，方案 C 退化为：两个独立 EGNN 图 + cross-attention 交互（即 EGNN 编码器 + 方案 B 的 cross-attention 路线）。

**完整方案 C 的结构来源选项**：
1. SAbDab 实验复合物结构（仅约 440 个 PDB，覆盖率极低，适合作为高质量验证子集）
2. AlphaFold-Multimer / Chai-1 / Boltz-1 预测复合物（计算成本高，CDR-抗原界面精度有限）
3. 退化版本：单体结构 EGNN + cross-attention（工程可行，几何信息仍来自结构）

**关键依赖**：EGNN（Satorras et al., ICML 2021）；`torch_geometric`

**优势**：最符合 E(3) 等变的物理动机；联合图上的消息传递天然建模了界面互作；是 AffinityEGNN 项目名称的"正名"方案。

**劣势**：完整版依赖复合物结构，批量对接计算成本高；退化版与方案 B 差异减小；模型结构改动最大，需要专门实现 `EGNNAffinityRanker`，无法直接复用 AffinityTransformer 的 `AffinityRanker`。

### 方案 D：ESM-3 多模态编码器

**核心思路**：ESM-3 原生支持三种 token 类型的组合输入：序列 token、结构 token（来自 VQ-VAE 量化的 3D 坐标，2048 类）、功能 token。模型在序列、结构、功能三模态上联合预训练，输出的残基 embedding 同时感知序列信息和空间信息。用 ESM-3 替换 AffinityTransformer 中的 ESM-2，其余不变。

**流程**：
```
抗体序列 → IgFold → 结构 → ESM-3 结构 tokenizer（VQ-VAE）
        \_____氨基酸序列_____/ → ESM-3 → [B, L, 1536]

抗原序列 → AF DB → 结构 → ESM-3 → [B, L, 1536]
                                   ↓
                             Cross-Attention → Attention Pooling → 打分头
```

**接口适配**：ESM-3 的 tokenizer 同时接受序列和结构输入，需要包一层适配器对外暴露 AffinityTransformer 兼容接口。ESM-3 开放 API 访问，完整模型权重需向 EvolutionaryScale 申请。

**关键依赖**：ESM-3（Hayes et al., Science 2024）；`esm` Python 包

**优势**：目前表达能力最强的蛋白质基础模型，在序列-结构联合理解上有大规模预训练；结构 VQ token 比 Foldseek token 信息密度更高（2048 类 vs 20 类）。

**劣势**：模型参数量大（300M～98B），inference 成本最高；需要申请权重；在消融实验中难以区分"结构信息的贡献"和"模型容量的贡献"，解释性差。

---

### 方案 E：ProteinMPNN Encoder 复用

**核心思路**：ProteinMPNN 有一个成熟的结构 encoder（原本用于逆折叠任务，将结构编码为残基特征后预测序列），可以单独提取其 encoder 部分，把蛋白质结构编码为每个残基的向量表示，不做任何序列生成。权重公开，代码成熟，部署简单。

**流程**：
```
抗体结构（IgFold） → ProteinMPNN encoder → [B, L, 128] → Linear → [B, L, d_model]
抗原结构（AF DB）  → ProteinMPNN encoder → [B, L, 128] → Linear → [B, L, d_model]
                                                                 ↓
                                                    Cross-Attention → 打分头
```

**接口适配**：ProteinMPNN encoder 接受 `(X, mask, chain_M, residue_idx, chain_encoding_all)` 的图格式输入，需要包一层适配器将标准 pdb 坐标解析为此格式，并对外暴露 AffinityTransformer 兼容接口。encoder 输出维度为 128，需经过 Linear 层投影到 `d_model`。

**关键依赖**：ProteinMPNN（Dauparas et al., Science 2022）；官方 GitHub 仓库

**优势**：在大量蛋白质结构上预训练（逆折叠任务），encoder 具备良好的结构理解能力；开源、无需申请权限、部署简单；相比 GVP-GNN 有预训练权重加持。

**劣势**：非等变（不满足 SE(3) 等变性）；embedding 维度仅 128，信息密度低于 ESM 系列；逆折叠预训练目标与亲和力排序的下游任务存在一定偏差。

## 9. 模型架构：共享框架与各方案插槽

除编码器外，AffinityEGNN（方案 A/B/D/E）与 AffinityTransformer 共享以下模块：

**Cross-Attention 交互模块**：在获得 `[B, L_ab, d_model]` 的抗体残基 embedding 和 `[B, L_ag, d_model]` 的抗原残基 embedding 后，使用交叉注意力机制学习抗体与抗原之间的条件依赖关系。该模块允许模型在抗原上下文下重新加权抗体残基信息，提供比简单拼接更细粒度的特征匹配能力。

**Attention Pooling**：将变长的残基级表示压缩为固定长度向量。通过可学习查询向量从残基级表示中提取关键信息，使模型能够在不同抗体长度和不同链结构下生成统一的全局表征。

**排序打分头**：接收聚合后的抗体-抗原交互向量，输出一个一维实数分数。该分数不对应具体的物理单位，而是表示模型对该抗体在当前抗原背景下相对优劣的判断。分数越高，表示模型认为该候选抗体越值得优先排序。

方案 C（EGNN 联合图完整版）是唯一的例外：联合图上的跨分子消息传递本身承担了交互建模，cross-attention 模块被替换，需要专门实现 `EGNNAffinityRanker`。

## 10. 训练目标：Pairwise RankNet Loss

由于任务评价指标关注排序一致性，训练目标也应围绕相对顺序设计。项目采用 Pairwise Ranking 的训练方式：在同一同质分组内抽取两个抗体样本，比较它们的真实标签高低，并要求模型输出的分数差与真实排序方向一致。

设模型对样本 $i$ 和样本 $j$ 输出的分数分别为 $s_i$ 和 $s_j$，模型认为样本 $i$ 优于样本 $j$ 的概率为：

$$P_{ij} = \frac{1}{1 + e^{-\sigma(s_i - s_j)}}$$

其中 $\sigma$ 是控制分数差映射敏感度的缩放参数。如果真实标签显示样本 $i$ 优于样本 $j$，则目标概率为 1；反之为 0。通过交叉熵损失优化大量样本对，模型逐渐学习在每个同质分组内部给出更合理的亲和力排序。

pair 采样策略（block_quantile / quantile_difficulty）与 AffinityTransformer 完全一致，复用其 `dataset.py` 实现。

## 12. 项目特点

本项目的核心特点可以概括为四点。

第一，任务表述更贴近评价指标和实际筛选需求。项目不直接追求绝对亲和力数值预测，而是将问题建模为同一抗原背景下候选抗体的相对排序，从而更自然地对应 Spearman 评价方式。

第二，数据处理强调可比性。通过同质分组和指标方向统一，项目尽量避免跨实验体系、跨指标尺度和跨抗原背景带来的错误监督信号。

第三，结构引入策略务实而非理想化。鉴于 SAbDab 亲和力标注稀缺的现实，项目不要求实验复合物结构，而是通过 IgFold + AF DB 为大规模序列数据提供结构补充，使结构感知编码器能够覆盖与 AffinityTransformer 相同规模的训练数据。

第四，五种编码器方案形成系统对照。从最轻量的结构 token 化（方案 A）到最严格的等变联合图（方案 C），跨越了不同的几何先验强度、预训练资源和实现复杂度，旨在通过实验数据而非先验判断来确定结构信息在亲和力排序任务中的实际价值。

## 13. 当前边界与后续方向

本项目的结构引入依赖单体结构预测（IgFold、AF DB）而非实验复合物结构。预测结构尤其在 CDR 环区可能存在局部误差，而 CDR 环区正是决定亲和力差异的最关键区域。这是当前方案的主要精度上限。

后续工作可以从三个方向推进。首先，在结构质量层面，对具有实验结构的 SAbDab 子集（约 440 个 PDB）进行专项分析，量化预测结构误差对最终 Spearman 指标的影响，并探索结构置信度（pLDDT）作为特征权重的可行性。其次，在方案 C 的完整实现层面，对核心抗原（SARS-CoV-2 spike、VEGF、lysozyme）的代表性抗体批量运行 Chai-1 或 Boltz-1 进行复合物预测，构建小规模高质量的联合图训练子集，验证完整 EGNN 方案的理论上界。最后，在模型集成层面，探索 AffinityTransformer（序列）与 AffinityEGNN（结构）预测分数的加权融合，作为比赛提交的组合策略。
